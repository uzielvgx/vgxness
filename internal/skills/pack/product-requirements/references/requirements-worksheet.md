# Requirements worksheet

Use this worksheet after framing the product decision. It supports lightweight, evolving product knowledge; it is not a backlog, delivery plan, or technical design.

| Area | Record | Evidence or decision needed |
| --- | --- | --- |
| Boundary | Product/feature, current state, decision owner |  |
| Users and problem | Affected users, context, unmet need |  |
| Outcomes | Desired user/business change and observable signal |  |
| Scope | Required behavior and constraints |  |
| Requirements | Per-requirement behavior and traceability to an outcome, constraint, evidence, or labeled assumption |  |
| Non-goals | Explicitly excluded behavior and review trigger |  |
| Acceptance | Observable criterion, preconditions, expected result |  |
| Uncertainty | Assumption, risk, dependency, open question |  |

## Review prompts

- Does each requirement serve an outcome, constraint, or clearly marked assumption?
- Could an independent reviewer observe the acceptance criterion without inferring an implementation?
- Has a solution choice, delivery task, API reference, or backlog item been mislabeled as a requirement?
- What evidence would revise the scope or non-goals?

The Scrum Guide supports lightweight, evolving product knowledge. It does not require a particular PRD format or prove a product outcome.

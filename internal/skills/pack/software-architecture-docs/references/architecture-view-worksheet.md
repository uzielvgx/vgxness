## ADR prompts

Record context, quality attributes and constraints, alternatives, decision, rationale, consequences, owner, status, and the event that reopens the decision.

## Review prompts

- Which stakeholder decision does this view support?
- Which statements are observed, proposed, assumed, or unknown?
- Does a claimed quality attribute have relevant evidence, or is it only an intended trade-off?
- Has this document drifted into a product brief, API reference, code review, implementation task list, or runbook?

ISO/IEC/IEEE lifecycle context can inform maintenance and ownership. It does not prove architecture quality, operational readiness, or compliance.

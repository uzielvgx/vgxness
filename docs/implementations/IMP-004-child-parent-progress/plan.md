## Decisions and assumptions

Authoritative decisions live in [progress.md](progress.md). Reading summary:

- Evidence is **documented** / **repository** / **runtime**; runtime is **none** in this mission.
- Event/UI visibility ≠ parent-context delivery ≠ parent-model action. Only the parent's own model action updates the canonical TODO.
- The parent is the **sole canonical plan/TODO writer** (persist before projecting); child progress is **untrusted bounded data**. A child may continue its **own scoped code edits** under the existing mutation grant; **plan files are reserved to the parent**, never simultaneous on the same path, with **at most one code-workspace writer** preserved.
- Provider behavior is **version-gated**, never assumed (Pi SDK `0.84.4` local vs app `0.85.1` observed; no signature assumption).

## Acceptance criteria

- **AC01** Capability claims distinguish documented / repository / runtime evidence; no runtime or feasibility claim without observed evidence.
- **AC02** A **typed, bounded** progress schema carries `planId`, `taskId`, `missionNonce`, `candidateBinding`, `seq`, `eventId`, `timestamp`, `reportType ∈ {progress|blocker|needs_input|result}` with bounded length; **correlation is not permission**; source assertions are separated from evidence.
- **AC03** The parent is the **sole canonical-state writer**: it **persists the plan before projecting** to TODO; a child claim is never marked done without evidence.
- **AC04** Rejection of stale / duplicate / closed-plan / wrong-candidate / old-mission-`seq` events; ordering, backpressure and overload handling defined; a pending decision stops dependent work.
- **AC05** **POC hard-trace gate.** True-live is proven by: **child alive** + **task call returned** + **event delivered** + **parent LLM emits `todowrite`** *before* the **child terminal** — a UI callback *enqueue* alone does **not** pass. The run must also show the **plan persisted before projection**. **T05 PASS is an aggregate**, not the trace alone: user POC authorization present **AND** T05a–T05e evidence all pass **AND** no unresolved blocking failures. A minimal isolated unit/integration sanity check runs **before any live call**, and the test/call budget is approved first.
- **AC06** Cancellation, child exit/ownership revocation, parent crash, late events, concurrency, one-writer preserved; no silent fallback; a persisted recovery checkpoint states truthfully whether the process actually survived (no restart-survival implication).
- **AC07** Independent verifier + CARE run against the **exact future implementation candidate**; **no approval now**.

## T06 production design defaults (reversible)

Authoritative decisions are in [progress.md](progress.md) (D38). Reading summary for
implementers:

- **Sync default preserved.** `task` without `background` keeps the existing
  synchronous terminal-envelope behavior and bytes unchanged.
- **Opt-in background.** `background:true` requires an explicit bounded progress
  binding `{planId, taskId}` plus the mission `nonce` (and `candidate` if supplied,
  preserved exactly). It returns a **stable opaque session-owned handle** immediately,
  never a terminal result.
- **Registered manager-only `task_control`** with `status|wait|cancel|close` over a
  handle. `wait` is bounded (default **≤1000 ms**) and never a busy-poll guarantee.
- **One process memory registry**, session-owned (not global across workspaces), with
  bounded **active** and **retained terminal** jobs. Finite lifetime: configurable
  `lifetimeMs` clamped to **1–15 min**, default **5 min**; no infinite jobs; **no
  restart-resumption claim**.
- **Progress is untrusted bounded data** (`progress|blocker|needs_input|result`),
  correlated `planId/taskId/missionNonce/candidate/seq/eventId`, UTF-8 bounded. The
  child tool derives identity from the immutable mission, never from model input.
  `result` never means accepted completion; a terminal execution state is not
  acceptance.
- **Parent is the sole canonical writer.** The controller never calls `todowrite`
  automatically. While a full background job retains mutation authority, the parent's
  managed `apply_patch` is limited to `docs/implementations/**` and native builtin
  mutating tools are **blocked fail-closed** via the `tool_call` hook; readonly
  coordination tools stay available. This is a guard, not a universal sandbox.
- **Platforms:** the existing Windows worker ownership failure remains fail-closed; no
  Windows claim is added. No daemon, broker, DB, or external transport is introduced.

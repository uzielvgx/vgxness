# CARE development-visible evaluation plan

This plan evaluates repository-visible routing and documentation behavior, not protected-holdout outcomes. Direct covers no-tool conversation, writing, and planning. Assisted covers bounded exact reads and evidence work; the plan also covers authorized actions, ordinary engineering, and assured high-risk work. Risk coverage includes ordinary and concrete critical boundaries; it must not turn a static check into an external adjudication.

Development cases include positive routing, negative non-activation, ambiguous requests that must fail closed or seek a bounded decision, adversarial attempts to bypass authority, coexistence with overlapping routes, and critical cases involving lifecycle, identity, or durability boundaries. Deterministic repository checks assert the documented route, risk, and boundary wording; their outcome is static conformance only.

## Protected-holdout boundary

An independent evaluator outside the repository exclusively owns protected holdout registration, custody, partitioning, contents, labels, graders, digest computation, runs, evidence validation, and adjudication. Only opaque, evaluator-issued, digest-bound evidence may support protected-holdout adjudication.

User-provided, repository-derived, fabricated, placeholder, manifest, or disclosed-holdout material cannot support protected-holdout adjudication. Missing, stale, malformed, mismatched, insufficient, or unavailable evidence is INCONCLUSIVE or BLOCKED, never PASS or VERIFIED. Repository tests establish static conformance only; they do not establish a protected-holdout result.

No external evidence schema, API, transport, dataset, or evaluator artifact is specified or stored by this repository.

## CARE coverage corpus and comparison protocol

`internal/orchestration/testdata/care-coverage-scenarios.json` is a visible development corpus, explicitly **not protected holdout** and **unexecuted behavior**. It binds static policy fragments to synthetic source snippets, fixtures, diffs, and receipts for flags/defaults, ambient state, newly reachable unchanged paths, inaccessible source, correction regressions, a narrow negative control, missing evidence, and infrastructure retry. Its Go conformance test validates schema, unique IDs, material kinds, role/policy bindings, and policy fragments separately; it does not compare a model summary with PASS or grade model quality.

This round is behavior UNEXECUTED and makes no improvement claim. If an independent comparison is later authorized, record baseline `a3d4247` and the proposed contract digest, with planned role, run identifier, candidate identity, and source receipt for each trial. Use fresh independent trials with the same model, settings, tool budget, cases, and grader configuration for both bindings. Give the agent only each case's materials, criterion, and usage scenario; withhold `policyAssertions`, expected labels, and forbidden behavior until the grader evaluates the retained trace.

Define denominators before runs: first-pass detection is known seeded defects correctly identified on the first semantic pass divided by known seeded defect opportunities per case and trial; unsupported PASS is insufficient-evidence trials with an unsupported PASS divided by all insufficient-evidence trials; false-positive rate is negative-control trials with a spurious defect or unnecessary block divided by all negative-control trials; late omission is preexisting defects first detected after the first semantic pass divided by all discovered preexisting defects whose source was available on the first pass; and administrative extra-call rate is extra administrative calls divided by all calls. Deduplicate findings within a case/trial. Report errors and no-results alongside each denominator, mark a zero denominator N/A, and report cost/time only when host-observed rather than inferred. Late-omission and continuation measurements require retained multi-round traces; single-response cases alone do not measure convergence. The gates are no unsupported PASS for inaccessible/insufficient-evidence cases, no unnecessary block for the well-evidenced negative control, known defects found on the first semantic pass, and raw comparison counts reported before any claimed reduction. No arbitrary percentage or sample-power claim is specified.

Known development cases remain separate from protected holdouts. Static conformance and documentation do not substitute for independent runs, retained provenance, or adjudication; this document specifies no API automation, cloud service, or holdout artifact.

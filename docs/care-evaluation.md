# CARE development-visible evaluation plan

This plan evaluates repository-visible routing and documentation behavior, not protected-holdout outcomes. Direct covers no-tool conversation, writing, and planning. Assisted covers bounded exact reads and evidence work; the plan also covers authorized actions, ordinary engineering, and assured high-risk work. Risk coverage includes ordinary and concrete critical boundaries; it must not turn a static check into an external adjudication.

Development cases include positive routing, negative non-activation, ambiguous requests that must fail closed or seek a bounded decision, adversarial attempts to bypass authority, coexistence with overlapping routes, and critical cases involving lifecycle, identity, or durability boundaries. Deterministic repository checks assert the documented route, risk, and boundary wording; their outcome is static conformance only.

## Protected-holdout boundary

An independent evaluator outside the repository exclusively owns protected holdout registration, custody, partitioning, contents, labels, graders, digest computation, runs, evidence validation, and adjudication. Only opaque, evaluator-issued, digest-bound evidence may support protected-holdout adjudication.

User-provided, repository-derived, fabricated, placeholder, manifest, or disclosed-holdout material cannot support protected-holdout adjudication. Missing, stale, malformed, mismatched, insufficient, or unavailable evidence is INCONCLUSIVE or BLOCKED, never PASS or VERIFIED. Repository tests establish static conformance only; they do not establish a protected-holdout result.

No external evidence schema, API, transport, dataset, or evaluator artifact is specified or stored by this repository.

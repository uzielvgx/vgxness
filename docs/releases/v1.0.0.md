# VGXNESS v1.0.0

Proposed first stable release. Publication is established by the matching GitHub
release and its successful tag workflow, not by this source document.

VGXNESS sets up OpenCode, Codex and Pi with shared project memory, portable
skills and a Manager that coordinates native workers and CARE reviews.

- OpenCode and Pi: choose one model for all seven agents or one per agent.
- Codex: retain the low, medium, high and ultra model plans.
- Pi: TypeScript/Node services and shared SQLite; no VGXNESS or Go runtime dependency.
- One current agent definition per role; receipt-backed updates and recovery.
- Structured SDD removed from active tools and workflows; historical data retained.
- Six platform archives, a portable Pi package, SHA-256 checksums and provenance.
- Checksum-pinned Homebrew and Scoop distribution manifests.

## Installation

macOS or Linux, with Homebrew installed:

```sh
brew install uzielvgx/tap/vgxness
"$(brew --prefix vgxness)/bin/vgxness" version
```

Windows, with Scoop installed:

```powershell
scoop bucket add vgxness https://github.com/uzielvgx/scoop-bucket
scoop install vgxness/vgxness
vgxness version
```

Install the desired coding hosts and configure their providers first. Then use
`vgxness tui` to configure integrations and models, or preview `vgxness setup all
--preview` before applying `vgxness setup all --yes`. A v1 release binary pins Pi
acquisition to its own tag. Package managers install VGXNESS, not coding hosts,
provider credentials or integrations automatically. If a managed launcher is
already on PATH, invoke the package-manager binary explicitly for upgrades.

See [the installation guide](../release.md) for direct downloads, ownership,
checksums, updates and rollback. Review [support limits](../v1-readiness.md):
Windows Pi workers are unsupported; hosts/repositories must be trusted; binaries
are unsigned; agent behavior and skill selection are not guaranteed. Additional
account-based model evaluations were intentionally excluded from this release.

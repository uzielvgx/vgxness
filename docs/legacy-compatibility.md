# Legacy Compatibility Matrix

This matrix records evidence-bound compatibility surfaces. Lifecycle labels distinguish **Current runtime** behavior, **Upgrade compatibility** for forward migration, **Historical recognition/repair** for exact known historical state, **Historical retirement** for exact removal-only handling, and **Current validation/recovery** for present manifest checks. No release status or retirement date is implied.

## Review rule

Historical bytes, digests, and schema migrations are compatibility evidence. Changing or removing one requires an explicit compatibility decision and focused evidence before it can be considered removable.

## Portable sync compatibility

Legacy local identifiers are not rewritten for sync. Outbound project-scoped transport uses durable deterministic wire-only identities instead; `resolve`, pull, and bootstrap translation remain unsupported.

## CARE compatibility boundary

CARE has no current fixed-lens aliases. Exact receipt-backed files support lifecycle upgrades; historical agent renderers are removed. [CARE architecture](care.md) defines those markers; [CARE evaluation](care-evaluation.md) distinguishes static repository checks from external adjudication.
